# 2026-11-15 实测数据的独立测量审稿

本次只读复核实际云端导出的校准、系统快照、GPU 采样、任务记录与清理回执；没有重跑或修改已执行的采集代码。时间均为北京时间。以下数字属于这一台机器、这一轮输入和配置，不能外推为跨机器统计结论。

## 校准：实测操作速率与物理上限分开

设备报告为 NVIDIA A100-SXM4-80GB，108 个 SM、计算能力 8.0，CUDA 可见总显存 85,094,825,984 字节。环境为 Python 3.13.16、PyTorch 2.14.1+cu130、CUDA 13.0、12 个逻辑 CPU。校准于 07:17:53—07:18:08 执行；默认各项 7 组，GPU/内存每组 5 次，使用原始样本的描述统计。

| 观察 | 7 组中位数 | 单位与解释 |
| --- | ---: | --- |
| 8192×8192 原生 BF16 GEMM | 283.220 TFLOP/s | 每次按 2mnk FLOPs；组间范围 261.162—283.504，不是模型算力 |
| 128 MiB 设备复制 | 841.284 GB/s | 单向 payload 计数 |
| 同一次设备复制的逻辑读+写 | 1682.567 GB/s | 2×payload；不是硬件 HBM 流量计数器 |
| pinned H2D / D2H | 12.302 / 13.169 GB/s | 分方向、顺序测量；不能相加当作单向带宽 |
| 单 CPU 内存复制流 | 10.416 GB/s | 逻辑读+写；包含缓存和 NUMA 条件 |
| SHA256 输入处理 | 0.371 GB/s | 指定 CPU 操作，不是通用 CPU FLOP/s |
| 32 MiB 文件写入并 fsync | 0.426 GB/s | 7 次共写 224 MiB，临时文件已清除 |
| 紧接写入的文件读取 | 1.585 GB/s | 未清缓存、很可能暖缓存；不是冷盘吞吐 |

GB、TFLOP 使用十进制；MiB、GiB 使用二进制。短时 GEMM 波动提示热身与时钟状态仍可能影响结果。7 组只是同一次运行的重复样本，不是 7 台设备或 7 次独立启动，不能给出总体置信区间。没有模型完整 FLOPs、实际 HBM/PCIe 流量和网络工作量，仍不能把这些速率代入后宣称得到完整生成物理下界。

校准 GPU allocator 的峰值 allocated 为 **411,174,912 字节（392.127 MiB）**，reserved 为 **425,721,856 字节（406 MiB）**。最后仍有 **8,519,680 字节（8.125 MiB）allocated**，记录明确为 **explicit_allocations_released=false**。不得改写为零或“进程内清理全部通过”。独立校准进程随后退出是另一层资源回收事实；仅凭 empty_cache() 不能推出 context 或云实例已释放。余留分配的具体来源未单独定位。

## 采样不是无扰动，也不是连续监测

采样期为 07:28:46—07:47:04，共 1084 次系统观察、545 次 GPU 观察，记录的探测错误为 0；采样线程最终均退出。

| 探测 | 中位耗时 | P95 耗时 | 最大耗时 | 最大相邻起点间隔 |
| --- | ---: | ---: | ---: | ---: |
| host.snapshot | 13.915 ms | 18.245 ms | 3013.021 ms | 6.787 s |
| nvidia-smi | 28.534 ms | 34.142 ms | 93.207 ms | 5.786 s |

P95 使用 nearest-rank 定义。两类探测累计墙钟占用分别为 18.839 和 16.035 秒，采样跨度约 1097 秒；它们在独立线程中运行，包含等待时间，**不能相加作为 CPU 开销或推理减速率**。没有开/关采集器的随机对照，故其扰动尚未量化。采样间隙不能用于证明瞬时显存、RAM、CPU 或功率没有超过某值。

GPU 采样观察到的最大显存使用为 73,386 MiB；这是采样最大值，不是连续硬件峰值。全采样期混合下载、加载、推理与空闲阶段，不应把全期 GPU 利用率中位数解释为推理效率。

## 实际预算、精度与任务口径

本轮预算记录给出 8 GiB 阶段 RAM 池、12 个 CPU 执行通道、1 个 GPU 宿主 CPU 通道，模型 RAM 预留估计 144 GiB、OS 预留 2 GiB。采样中最多接纳 2 个执行尝试；CPU 通道最多使用 2 个，其中 GPU 宿主 1 个、CPU 阶段 1 个；阶段 RAM 最大预留 1,309,827,072 字节（1.220 GiB）。这些是准入/预留账本，**不是模型总 RSS**。任务资源记录中的进程 RSS 已到 146,221,989,888 字节（136.180 GiB），不应拿它直接与 8 GiB 阶段池比较而宣称越界或无越界。

原生池记录为 PyTorch intra/inter-op 各 1、已观察 OpenMP/BLAS 池各 1。I/O 策略仍明确为 **disk_capacity_only、bandwidth_calibrated=false**：独立执行了磁盘校准，并不意味着调度器已经按带宽动态准入。

两个成功任务的实际回执均为 precision=bf16、attention_backend=native、Turbo lightx2v-ref2va-4step、5 个调度点/4 次模型评估、无风格 LoRA；排队取消任务的 effective 仍为 null。启动级 runtime_options.attention_backend=auto 与逐任务 effective 的职责不同，不应混为同一时刻的实际选择。设备支持和运行回执不能代替对每个权重、激活、累加指令的全面精度审计；官方 FP32 例外仍需单列。

第一/第二任务内部 pipeline 墙钟分别为 **515.331649 / 180.869920 秒**，对应进程 read_bytes 增量为 **136,419,201,024 / 87,388,160 字节**。它们内容不同、执行顺序固定、缓存/驻留/首次执行状态不同，且计数器作用域是整个模型进程；不能据此归因于并行调度、Turbo、磁盘或某一种缓存，更不能称为加速比。跨阶段重叠时，进程资源增量也不可相加归到各任务。

第二任务的 metrics.wall_seconds=697.799898 包含其预处理后等待 GPU 的时间，不等于它的 GPU 推理时长。阶段事件给出的 GPU 主机作用域约为 515.339 / 180.942 秒，整体阶段跨度 698.206 秒，CPU/GPU 作用域交集 3.502 秒；这些支持“本轮存在真实阶段重叠”，但无实测串行对照，不能把阶段时长之和减去跨度当作已测到的系统加速。

## 可支持的结论与保留问题

本轮记录支持特定配置下的阶段因果、排队取消、观察到的 GPU 阶段互斥、独立 CPU/GPU 工作重叠与有回执的资源释放；阶段包围事件没有覆盖租约 acquire/release 的全部边界，不能冒充完整租约审计。最终另一次 nvidia-smi 计算进程查询为空。平台释放仍使用独立平台观察，不由该空列表自动推出。分析器通过是有限记录的一致性检查，不是任意负载、故障时序或无限队列的普遍正确性证明。
