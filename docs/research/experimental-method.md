# 从架构假设到可复核实验

本文件是 2026-11-15 的研究协议，结果尚未写入。目标是为当前单机、单 A100、原生 BF16 的 H3 服务建立一组可重复、可反驳的条件命题；不把有限实验升级为所有模型、云平台或负载的普遍定理。

机器入口为 [research/protocol.json](../../research/protocol.json)。既有 [A100 验收](../../evidence/acceptance-2026-11-15.json)只作为历史基线；本轮结果必须有新实验身份、源码身份、实际设备、内容身份和独立回执。

## 本轮要补的理论空白

| 空白 | 可观测补充 | 仍不能推出 |
| --- | --- | --- |
| 下载、服务就绪、任务可开始容易混成单一 ready | 同一实例的 API 可达、模型 ready、接收/派发/阶段事件时间线 | 一个时间线能证明所有故障排列正确 |
| “子事件可并行”只有结构说明 | 两个真实任务的阶段占有区间、预算与实际重叠 | 占有 GPU 租约等于 CUDA 内核一直繁忙 |
| “资源足够”可能只是配置值 | 当前有效 CPU 配额、RAM/磁盘估计、GPU 租约和采样观测 | 保守估计就是实际内存峰值；抽样能证明没有瞬时超额 |
| 取消与完成、清理与释放混淆 | 取消仲裁、派发记录、终态、任务清理、进程退出和平台会话分别对账 | 查询失败或失联就是释放完成 |
| 理想物理下界被实测耗时替代 | 把硬件上界、实际工作量、微基准、阶段轨迹分开建账 | 一次实验能证明全局最优或通用加速倍数 |

## 实验单位与固定条件

最小单位是 `experiment_id / host_instance / code_revision / job_id / attempt_id / content_id`，不能用“同一个按钮”替代身份。记录 Python、PyTorch、CUDA、驱动、模型来源/版本、注意力后端、LoRA 身份、实际步数、分辨率、帧数、音频/视频参考参数及预算。公开记录不含密钥、私有连接或原始用户媒体。

本轮使用完整 A100 及原生 BF16 主干，保留官方 FP32 例外。不以 80 GB 推断 SXM/PCIe 形态，不套用不匹配的峰值；若实际设备、内存或依赖不能满足预检，记录阻断并释放，而不是改用量化让实验“通过”。所有生成内容与历史任务不同，各任务也用不同的内容身份；输入形状、参考数量、模态和生成参数尽量匹配。

先冻结有限计划与输入清单，再运行。已观察结果后修改假设或阈值，必须保留旧版本、原因及新实验身份。失败、重试和被取消任务均计入实验记录，不只保留成功片段。

## 有限运行顺序

1. **本地校准检查**：验证分析器能拒绝缺事件、反序、跨实例、重复身份和超预算轨迹；这些是 CPU 证据。
2. **云实例与测量前检**：记录实际硬件、软件、源码与可用预算。如果执行微基准，明确它与服务负载互斥；不在模型下载/加载时测“空闲机器带宽”。先保留冷启动条件，不能把缓存状态未知写为冷缓存。
3. **一次正常冷启动**：启动管理器、API、模型及已选公网。公网可达后立即接收至少两个保留任务与一个待取消任务；观察接收时模型确实未就绪。若错过该窗口，H1 的本轮结论为未充分检验，不为制造窗口无界重启。
4. **排队、取消、真实执行**：以新内容提交有限批次，取消一个仍排队的任务。至少两个真实生成任务用匹配输入形状与参数，保留它们的预处理、GPU、编码校验和清理事件。取消发生得太晚时记录真实阶段，不冒充“排队取消”。
5. **产物与表达对账**：API 终态、请求/生效参数、完整媒体校验、外部下载字节数及 SHA256 对账。面板与日志按实例/任务身份检查同一语义，不要求字符串相同。
6. **停止与资源释放**：停止新接纳、收敛已接纳任务，保存最终任务与进程清理回执。最后由平台确认云实例不再分配。API 失联是连接观察，不能代替释放证据。

本轮首先是一次架构探索实验，而非可靠性统计或性能排名。若资源允许，后续独立重复相同协议；不在协议里用“直到通过”为停止规则。事故恢复最多执行事先声明的有限次数；已接收但响应未知的提交先按原身份查询，不能重复生成。

## 可证伪的架构假设

| ID | 有条件的命题 | 需要的观察 | 反例 / 未充分检验 |
| --- | --- | --- | --- |
| H1 | API 及隧道具备接纳条件时，无需等待模型 ready 才接收任务；模型未 ready 时不会进入 GPU 阶段 | 同实例公网查询、接纳时快照、模型 ready 与阶段事件 | 下载期间已 GPU 派发为反例；没有在未就绪窗口提交则未充分检验 |
| H2 | 每个尝试遵循 prepare→GPU→encode_validate，GPU 租约互斥，声明的 CPU 租约不超过有效预算 | 成对阶段事件、预算、实例与尝试身份 | 依赖反序、两 GPU 区间重叠或声明租约超额为反例；事件缺失不能判安全 |
| H3 | 当前有足够预算的独立 CPU 阶段能够与另一任务 GPU 阶段重叠 | 跨任务区间交集，以及工作已就绪/预算可取的证据 | 有持续可行机会却被全局阶段屏障阻塞为反例；没有可行机会或交集小于测量误差则未充分检验 |
| H4 | 排队取消被仲裁后，该尝试不会再得到 GPU 租约，并有可查询终态和清理结果 | 取消请求/接收、派发、阶段、终态 | 仲裁后的派发或终态丢失为反例；只有客户端发送时间无法确定取消先于派发 |
| H5 | 请求配置与实际应用分别可追踪，BF16/FP32 路径及插件/步数符合选定策略 | requested/effective、精度早检、实际生成回执 | 把 requested 当 effective、静默量化、插件状态泄漏为反例；无实际应用观察则未知 |
| H6 | 同一被接受的尝试只有一个提交结果；查询未知不会导致客户端重新生成 | 原任务身份的完整事件、终态与产物身份 | 同一请求意图重复生成且无新显式尝试为反例；本轮未注入丢响应只能报告正常路径 |
| H7 | 成功意味着经完整校验的产物可按同一身份下载，且外部字节与提交产物一致 | 媒体检查、API、下载哈希/字节数 | 下载不完整、哈希/身份不符为反例；可播放预览不能单独证明完整文件 |
| H8 | 任务清理、进程停止、平台释放是分别可验证的闭环 | 任务清理、进程退出、最终宿主回执、平台会话 | 假成功、遗留持有者或缺失必需清理为反例；平台不可观察时释放结论未知 |

每条命题报告 `supported_in_observed_scope / refuted / inconclusive / not_run`，附对应原始证据身份和覆盖范围。“未发现反例”不等于已证明。如果完整测量链缺一环，即使视频生成成功，也不能给全部假设填“通过”。

## 时钟、测量侵入与误差

阶段耗时采用同一时钟域的单调时间。每条记录关联宿主/启动身份；跨宿主的 `monotonic_ns` 不可直接相减。UTC 用于人类相关性，客户端请求往返时间用于外部体验；两者不能替代服务端阶段时间。轮询状态只确定变化发生在“上次未见—首次见”的区间内，不将首次看到的时刻当作真实发生时刻。

现有模型阶段事件记录的是**租约内的工作包围区间**，包括主机工作、等待和审计成本，不等于纯 CUDA 内核耗时。GPU 工作异步：按 CUDA 流记录事件或在已有同步边界取耗时；不可为了每个采样点做全设备同步而把原来的并行变为串行。相关流必须覆盖实际工作；一个流上的时间不能自动代表所有流。依据 [NVIDIA CUDA 异步执行文档](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/asynchronous-execution.html)和 [CUDA 计时说明](https://docs.nvidia.com/cuda/cuda-c-best-practices-guide/#timing)。

对事件写入、fsync、采样和查询记录频率与开销范围。轻量计时采用已有阶段边界；性能剖析另设样本，避免把剖析开销归因于架构。缺少时钟精度或写入延迟上界时，报告原始区间，不把亚毫秒交集解读为有意义并行。

GPU 利用率、CPU 使用率、RAM/显存峰值若来自定期采样，只能说“观察到的样本最大值”。声明预算是准入约束，不能冒充实际消耗测量。通过完整租约事件重建的最大占有量，与采样到的硬件利用率分别报告。

## 内容唯一性与因果推断

用户要求每次测试全新内容，因此不能悄悄重复旧视频做 A/B。当前有限运行可以固定形状、步数、模态、参考数量和冷暖状态，并在后续实验中随机分配全新匹配内容到策略组；这样减少但不能消除内容混杂。仅两个不同内容任务的耗时差不能证明插件或调度的加速倍数。

同一条并行轨迹中，把各阶段耗时相加可得到“按本次测得阶段时长串行拼接的经验参考”。它不是一次真实串行对照：并行会改变缓存、CPU 竞争、内存带宽和阶段耗时。将此参考除以实际批次时长，只能描述区间重叠结构，不能命名为实际加速倍数。

单批次只报告每个样本和范围，不用三个样本声称稳定 p95 或置信区间。即使独立同分布条件成立，零失败样本也不证明失败概率为零；条件未知时不强套统计模型。任何图表都同时显示样本量、遗漏和失败记录。

## 模块知识如何更新

一次实验可以把特定条件加入“客观具象条件”，为一项可选策略增加证据，并校准候选指标；它不能把主观需求或策略选择变成物理定律。对被反驳的假设保留反例及修订原因。用不同表达展示同一结论时保留条件、身份、未知与失败，避免从图表摘要重新生成更强的论断。

本轮后仍需独立研究：多平台复现、长时间到达流及过载稳定性、真实故障注入、完整 FLOPs/HBM 工作量、带宽争用模型、画质/语义质量以及任意模型接口可迁移性。固定队列无条数上限不意味着有限资源能承受无限积压。
