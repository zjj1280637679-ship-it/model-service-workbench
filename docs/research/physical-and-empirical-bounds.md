# 物理下界、经验参照与可实现调度

理想全并行物理极限是本项目的参照物，但“理想”必须保留真实依赖、共享资源与正确工作量。把不存在的无限带宽、重复命名的同一 GPU 或尚未满足的前提加入理想模型，会得到没有工程意义的数字。

## 三类数值分别建账

| 类型 | 输入 | 能支持的判断 |
| --- | --- | --- |
| 乐观物理必要下界 | 已知工作量、匹配执行路径的物理容量上界、依赖图 | 声明工作范围内不能比该值更快；不保证可实现 |
| 经验能力参照 | 有记录的微基准样本、设备/软件/功耗/形状和测量方法 | 当前实验条件下某类内核或传输达到过的速率；不是未来工作负载的物理上限 |
| 运行轨迹参照 | 真实任务阶段耗时、占有区间与依赖 | 本轮经历了什么、哪里等待/重叠；不是未执行策略的真实耗时 |

实测微基准吞吐通常低于硬件峰值。将它代入分母得到更大的时间值，不自动成为严格下界：另一实现或形状可能更快。应标为 empirical reference，不能和 physical lower bound 共用未注明来源的字段。

厂商标称峰值也须说明操作计数、稠密/稀疏、时钟与设备形态；未确认它确实约束当前设备时，只能称为规格参照。严格必要下界的推导以 c(r) 是相应工作路径的有效容量上界为条件，不靠给一个数字命名为“峰值”来满足前提。

## 必要下界的推导与条件

对节点 i、共享资源 r，工作量为 w(i,r)，容量上界为 c(r)，两者单位匹配。若工作量为所有实现都必须执行的量，该约束适用于那些实现；若来自当前程序的计数，则只适用于执行这些工作量的实现。算法改变或缓存重用改变工作量时须重新建模。

```text
l(i) = max_r w(i,r) / c(r)
L_resource = max_r sum_i w(i,r) / c(r)
L_path = max_path sum_i l(i)
L = max(L_resource, L_path)
```

推导：任何长度 T 的可行执行，在资源 r 上最多完成 c(r)T 的工作；每条真实先后路径的节点时间不能重叠。因此 T 至少同时大于资源工作量下界与路径下界。不同资源的 node 项取最大值假设理想重叠；如果节点内部存在已知不可重叠的阶段，应拆为有依赖的节点。

这些仅是必要约束。离散调度、非抢占阶段、有限 RAM/VRAM、中间产物驻留、同步和不同阶段争用，可能使可实现最小时间严格大于 L。满足下界也不能推出某个贪心策略达到最优。当前 [performance_model.py](../../runtime/minimax_h3/performance_model.py)实现这个乐观模型，并明确工作量覆盖范围。

## Roofline 的正确作用范围

简化的 Roofline 参照同时考虑运算工作量与对应内存层的数据搬运；低并行度、启动延迟及指令开销可使任务远低于这些上界。大矩阵的 BF16 吞吐不能直接套给归一化、解码、CPU 编码或网络阶段。参见 [NVIDIA GPU 性能背景](https://docs.nvidia.com/deeplearning/performance/dl-performance-gpu-background/index.html#understanding-performance)。

HBM 流量包括读与写，不能用模型文件大小代替。L2、HBM、PCIe 与网络属于不同测量对象；双向接口标称值不能当作单向传输能力。准确 Roofline 需要同一工作区域的耗时、FLOPs 和相应层次的字节计数；微基准用于刻画机器能力，应用剖析用于刻画应用，二者不能互代。参见 [NERSC Roofline 方法](https://docs.nersc.gov/tools/performance/roofline/)。

对本项目，BF16 Tensor Core 工作、官方 FP32 例外、CPU 媒体处理、HBM 和主机传输分开计数。计数器不可用或覆盖不全时保留 unknown/partial；禁止通过已有总耗时反解出一个“工作量”，再把同一耗时宣称为验证成功。

## 阶段区间给出的经验事实

令每个阶段租约的有效区间为 [s_i,e_i)，持续时间 d_i=e_i-s_i。区间重建前先核对时钟域、身份、配对、单调性和重复事件。

```text
跨任务 CPU/GPU 重叠 = measure(union(CPU intervals) ∩ union(GPU intervals))
批次包围时间 = max_i(e_i) - min_i(s_i)
阶段持续时间合计 = sum_i(d_i)
GPU 租约占有率 = measure(union(GPU intervals)) / 明确定义的观测窗口
```

先求并集再求交集，防止两条 CPU 区间同时重叠一个 GPU 区间而重复计时。GPU 租约占有率不是 GPU 内核利用率；阶段包围时间不含窗口外排队、下载或平台分配。端到端指标另按请求接纳或用户启动到可下载的约定窗口计算。

声明阶段耗时不变、资源池固定，才可以把阶段时长代入一个调度模型讨论该模型的最短时间；这是经验调度模型的数学问题，不是硬件第一性原理。若模型枚举发现更好方案，仍需真实执行检验竞争和缓存变化后是否成立。

## 本轮结论的允许形式

允许：“在该实例、配置和有限输入批次中，观察到 CPU 编码与下一任务 GPU 租约重叠 x 秒；未观察到两个 GPU 租约同时持有；测量覆盖/误差如下。”

不允许：“系统达到硬件极限”“全部并行最优”“本次单次成功证明长期稳定”“不同内容两个耗时之比就是加速倍数”。缺少完整工作量时，整体物理效率继续未知，这个空白本身也是明确的研究结果。
