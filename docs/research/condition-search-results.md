# 客观条件集合：设计、搜索与验证结果

仓库 0.3.0 增加离线研究工具，把“列出条件”推进为“声明模型、搜索候选、给出反例、核对证据”。本轮没有新申请 GPU，没有修改生产调度、精度或笔记本布局。

入口为[设计规范](objective-condition-sets.md)、[四模块×四视角源码审查](condition-source-audit.md)、[8 个有限模型](../../research/condition-models.json)、[实际运行回执](../../evidence/conditions-2026-11-15/report.json)。源码审查覆盖 16 个模块视角单元；这个覆盖数不表示客观世界中的所有条件已经找到。

## “充分”怎样判定

给定模型约束 C、候选条件集合 P、目标 Q：先要求 C∧P 至少有一个允许状态，再完整检查是否存在 C∧P∧¬Q。没有这种反例，才称 P 在本模型内充分。约束不一致、前提不可满足、世界预算不足分别报告，不以矛盾前提的空真冒充成功。

搜索返回所有**包含极小**充分集合：删掉其中任一条件都会失去充分性。条件数最少、检索成本最低、延迟最低是其他问题，不自动等价。必要条件单独检查 C∧Q 是否可满足，以及它是否蕴含候选项；它不是全部极小集合的交集。

这些模型的目标有一部分就是声明的审查规则。搜索展开了这些规则的逻辑后果，不能把规则定义与约束假设包装成经验发现，更不能证明实际服务未来必然成功。

## 本轮实际搜索

8 个模型均完成限定空间内的搜索，共得到 9 个包含极小集合；第八个示例有两条替代路径。完整布尔状态、必要条件、集合与搜索计数均在回执中。

| 审查目标 | 主要条件组合 | 特意不加入的无关屏障 |
| --- | --- | --- |
| 新上传进入持久队列 | 鉴权、请求合法、上传提交、队列开放、存储可用 | 模型下载/就绪 |
| 公网 API 交付 | API 可用、隧道存活且连接、同实例探测、观察新鲜 | 模型就绪；这里指 public_api_ready |
| 管理器发出执行邀约 | 拥有排队任务、派发策略开放、模型 ready、worker 存活且接纳 | GPU 当前空闲 |
| 容器接纳新的执行尝试 | 模型可用、接纳开放、请求身份有效、尝试无重复、输出无冲突、RAM/磁盘预留 | GPU 当前空闲；幂等重放另建分支 |
| GPU 阶段允许开始 | 模型 ready、预处理成功、未取消、GPU 与宿主 CPU 的原子授予回执 | 下载完成不能替代 ready |
| 成功产物可提交 | 结果身份、局部清理、产物归属、存在、长度、哈希及媒体验证 | 客户端已经下载 |
| 历史生命周期闭环 | 任务终态、任务清理、服务进程退出、平台释放分别有证据 | 不能只凭服务退出 |
| 两种证据路径示例 | `{独立本地验证}` 或 `{可信提交回执, 外部字节匹配}` | 不能只保留条件数更少的那条 |

上表是布尔聚合，不是完整生产路由实现。例如“请求合法”仍要展开为上传大小、参数、实例、尝试及格式等检查。GPU 模型在声明 `prepare_succeeded⇒attempt_owned` 后，可以从极小集合省去重复的 attempt_owned；**这不是删除运行时所有权检查的依据**。只有同作用域的真实不变量成立，这个逻辑约简才有效；不变量失效要重建模型。

程序返回了三个可重放的弱前提反例：

1. 下载完成、资源授予等成立，但 model_loaded/model_ready 为假，不能推出允许 GPU 阶段。
2. API 和隧道都存在且已连接，但同实例公网探测为假，不能推出公网 API 交付。
3. 任务和服务清理均有记录，但平台释放为假，不能推出完整资源释放。

它们是声明模型中的反例状态，不伪称本轮新发生了三次实际故障。是否真实可达以及哪个机制排除它们，需要源码、状态转移模型和真实故障实验继续约束。

## 客观证据怎样核对

`audit_evidence` 读取 JSON 文件的精确字段，先核对源文件 SHA、源内实例身份指针和查询身份，再核对半开有效区间 `[from, until)`，最后按显式值映射得到真、假、未知或冲突。

- 缺字段、源文件变化、身份不符、过期、未来观察、策略声明不充当有效事实；记录排除原因，结果保留未知。
- 同身份、同有效窗口中存在真与假，保留冲突，不使用“最新一条覆盖”掩盖问题。
- 数值 0 与布尔 false 不混用；未识别值为未知，不能用语言的 truthiness 推断。
- 显式 source binding 需在源文件中逐项匹配，不能仅靠外层记录贴上当前实例 ID。
- 哈希只核对字节。观察者是否可靠、JSON 是否准确反映现实以及有效期是否合理，仍需独立审查。

本轮重读 0.2.0 的真实 A100 实验材料，而不启动新服务。11 个布尔条件中：**6 真、1 假、4 未知、0 冲突**。

| 状态 | 条件及范围 |
| --- | --- |
| 真 | 终态覆盖、任务清理、服务退出、平台释放、观察到的 GPU 阶段不重叠、同实例 ready 门控；仅针对旧实验记录 |
| 假 | 选定历史快照中的主流水线带宽准入已校准；字段实际为 false，不否定独立微基准已经测过带宽 |
| 未知 | 全部 GPU 租约 acquire/release 轨迹、完整模型工作量、当前新实例的 ready、网页面板语义重新实测 |

历史闭环四项条件在其回顾窗口内具备证据，足够满足本次声明的闭环审查规则；它们不授权任何新实例开始工作。回顾窗口刻意绑定旧生命周期，不能被当作运行时 TTL。图像/模型内容、性能数据、任务结果均引用原实验，不增加真实 GPU 样本数。

## 实现边界

本轮实现：有限布尔建模、显式别名归一、直接目标或其否定/单成员包装的前提禁入、不可满足检查、全部极小集合搜索、具体反例、世界/子集预算截断、来源字段与四值证据复核。73 个独立 CPU 反例测试已通过。

当前上限为 16 个布尔变量、20 个候选 literal，默认最多检查 65,536 个完整赋值和 65,536 个未剪枝候选子集。预算是枚举量上限，不是硬实时保证。世界搜索未完成时不产生充分性证明；子集搜索截断可以保留逐个已经完整验证的集合，但不能宣称找齐所有集合。剪枝仅排除已证集合的超集。

尚未实现自动发现未声明的语义别名、跨来源循环依赖、完整物理变量/单位推断、数值连续域求解、来源可信度认证或真实故障自动实验。它也没有连接生产调度器；执行前的原子资源仲裁和执行后的完成验证仍由现有运行时负责。设计文档中的全流程是扩展目标，不能据此宣称这些缺口已经实现。

## 复核

```bash
python research/run_condition_study.py --output condition-report.json
python -m pytest tests/test_condition_sets.py -q
```

第一条命令重算 8 个模型、3 个反例、历史证据的身份与字段，再独立重放旧 trace 分析；不访问网络、不启动 GPU。生成时间会变化，比较模型结果与源文件指纹，而不是要求整份 JSON 字节不变。

单模型可用 `python research/condition_sets.py model.json --output search.json`；加 `--premises premises.json` 则只验证给定集合。`model.json` 使用目录中某一个模型对象，不是整个目录。目标自证、无解模型、预算截断与不充分集合返回非成功状态，并保存原因或反例。
