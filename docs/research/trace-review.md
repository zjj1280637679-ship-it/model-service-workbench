# 2026-11-15 单实例实测独立审稿

本次审稿只读核对真实事件流、终态任务回执、客户端状态与请求审计、下载文件及平台释放截图。未修改运行实现，也没有重新申请 GPU。审稿日期与下述本地时间均为 Asia/Shanghai。

## 阶段时间与可解释的结论

以下秒数来自同一模型实例的 `monotonic_ns`，不是 CUDA 核函数计时。阶段包含宿主执行、I/O、同步及 CPU 产物交接的实际范围。

| 任务 | 预处理 | GPU 阶段范围 | 编码与校验 |
| --- | ---: | ---: | ---: |
| A | 0.024826 | 515.339016 | 3.430405 |
| B | 0.079349 | 180.941534 | 1.883115 |

独立由事件端点重算，两段 CPU/GPU 交集的并集长度为 **3.501832783 秒**。首个预处理开始至最后编码校验结束的范围为 **698.205961468 秒**。这支持“确实发生了交叠”，不等于节省了同样的总时长：本轮未运行串行对照，也未证明串行条件下各阶段耗时不变。

A、B 内容不同，而且处于第一次和后续推理位置。其 GPU 阶段时长之比不能解释为策略加速倍数。进程读取计数在 A 的 pipeline 范围增加约 136.419 GB，在 B 增加约 0.087 GB，是冷启动数据移动影响的线索；计数明确为进程范围且存在并发阶段，不能把它当作各任务独占 I/O 流量或据此确定全部差异的因果。后续实验需要独立控制缓存/初始化状态、记录数据移动，并在全新内容约束下进行多样本匹配与随机分配。

客户端普通 JSON 请求的审计区间包括响应读取；流式产物下载的 HTTP 区间止于响应头。因此本轮不能从该区间计算完整视频下载带宽。

## 反例、缺口与证据边界

审稿过程中发现并修复的是分析器的证据判断缺陷：正常停止快照缺失模型字段被误判、遗漏终态任务回执仍可全通过、旧实例释放凭据可被复用、清理布尔值掩盖非空存活 PID、GPU 就绪门控缺失，以及仅凭连续事件前缀宣称生命周期完整。相应反例已纳入 CPU 测试；这类测试证明分析器能够拒绝指定错误输入，不增加真实 GPU 样本数。

硬件微基准自身留下了一条不能抹掉的中间结果：其结束时 `explicit_allocations_released=false`，仍观察到 8,519,680 字节已分配设备内存。这不是“微基准显存已归零”。后续服务进程退出、GPU 计算进程为空及平台释放分别有最终证据，支持最终资源闭环；不应回写中间观测为成功。

本轮没有稳态到达/过载实验、故障注入、跨平台重复、完整模型 FLOPs/内存流量计数或画质对照。物理必要下界、微基准实测参考、这份阶段事件时间线仍是三类不同对象；不能从其中任何一个直接推出整体推理效率或数学最优分配。
