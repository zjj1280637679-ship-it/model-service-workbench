# 条件更新后的策略与指标技术债

本次以 v0.4.0 为需求基线，逐一复审四模块、十六个视角。所有 requirements 文本保持一致；输入是当前源码、CPU 反例和已经完成的 A100 实验。本轮没有申请 GPU、修改运行时代码、调整界面布局或改写历史运行证据。

发现 **12 项债，修正 4 项，保留 8 项待清偿**。债项不是把所有可选方案都实现一遍：未采用的策略、诚实保留的未知，以及历史实验本来没有测量的目标，不自动构成 bug。只有已变化的条件与当前选择、解释或验证之间出现可定位的失配，才登记在此。

## 已修正

| 债项 | 不变需求与新条件 | 原有失配 | 本轮结果 |

| TD-001 / P1 | 资源不能重复借出；已有完整租约及容量版本 | 版本字段全删仍可 pass；同版容量变更也未拒绝 | 容量版本必须绑定内容，缺证据为 unknown，矛盾为 fail；新增反例。合法历史结果不变。 |
| TD-002 / P1 | 指标口径可复算；CPU/GPU 完整而 RAM/磁盘不完整 | 全资源总指标最新值0，仅在长文本中限定子范围 | 新增 `EO-REC-CPU-GPU-OVERCOMMIT=0`；全资源 `EO-REC-OVERCOMMIT=unknown`。原0.4.0标签仍可追溯。 |
| TD-003 / P2 | 模块表达当前事实；新增阶段条件及新实测窗口 | 模型契约仍只留旧租约缺失、API混淆ready/接纳、文档混称“本轮” | 并列0.2/0.4窗口，补产物2/2与GPU租约0，更新新字段；全资源清理、控制p95和UI同源指标仍未知。 |

TD-001 的反例是在真实公开轨迹的内存副本中删字段或改变值，不改原始文件。修复后的条件分析对合法 0.4.0 轨迹仍为 **7 pass、2 unknown**，逐字段等同旧结果；两个未触发 GPU 故障分支没有因本次 CPU 修复变成已实测。

TD-002 修正的是当前知识记录的解释与归类，不是补造历史数据。原 CPU/GPU 零值及其证据移入专用子指标，旧0.2观察保留；0.4全资源总指标缺口明确记录。不存在“换了一个指标名就完成全资源验证”。

| TD-010 / P2：历史CI重放 | 旧轨迹默认与当前runtime源码比较 | 下一次合法运行时修复会触发历史SHA冲突；先绑定固定历史源，再独立验证当前实现，不能回写历史指纹。 |
| TD-011 / P2：实验导出复用 | 本轮专用导出器硬编码旧基线和变更说明 | 旧导出无错，下一实验直接复用会产生错来源；新增显式协议/基线/源码/干预输入并拒绝缺失。 |
| TD-012 / P2：指标重算 | 知识检查只验证数值形状，不核对完整算术和证据映射 | 错分母、错实例或部分覆盖仍可能结构合格；为已选指标增加按身份、窗口、资源范围重算，未支持项不补零。 |

执行依赖是：**先清偿 TD-010，避免下一轮运行时改动误伤历史重放；再共同处理 TD-004/005 的当前证据投射，以及 TD-006/007 的审计保存和查询成本**。这些分支可独立实现和CPU验证，最终在新版本合并后按需要做一次新的受控GPU验收。TD-008 需要先明确公平与吞吐的评价方法；TD-011 在下一实验采集前完成，TD-012 可独立推进。

本次不根据短批次的3.212秒主机阶段交叠、单个p95缺口或合成快照大小推导A100加速倍数、物理最优或必须替换FIFO。带宽、完整工作量、质量和统计对照不足的项继续按各自证据边界报告。

## 可执行的复审边界

机器账本为 [strategy-metric-debt.json](../../knowledge/strategy-metric-debt.json)，每项绑定需求范围、新条件、落后的决策、指标、来源、处置和关闭验收。复审快照为 [condition-reviews.json](../../knowledge/condition-reviews.json)。运行：

```bash
python tools/check_condition_reviews.py
```

检查器逐项验证16个视角的需求基线及已审条件、策略、指标摘要，并核对声明的源码/证据输入。变化时返回 `review_required`；状态为 `current` 只表示本次复审尚未过期，仍会列出开放债项，不表示技术债清零、条件穷尽、语义证明或GPU验收。

`freeze_sources.py` 只更新普通源码清单，不更新这份复审快照；本工具也没有自动刷新模式。维护者应读实际差异、重审受影响的策略/指标并更新债项之后，才记录新的复审指纹。这仍是一份有边界的人工审查记录，不会自动发现未纳入来源集的新条件，也不能防止人为伪造复审。

本轮验证记录见 [repository-validation.json](../../evidence/repository-validation.json)。v0.4.0 的GPU原始观察、分析结果和历史来源均保留；本轮新增的是离线反例、契约纠偏与复审检查。
