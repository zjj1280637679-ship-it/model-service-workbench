# 知识模型：四类判断 × 四个视角

这是本项目采用的工作模型，不把“主观/客观”当作高低等级，也不声称它是已经证明完备的世界分类。目的在于让愿望、观察、选择和评价各归其位，任何结论都有可追踪的来源与作用域。

## 四类分别回答什么

| 类别 | 回答 | 应记录的内容 | 典型错误 |
| --- | --- | --- | --- |
| 主观抽象的需求 | 想实现什么效果，为什么值得实现？ | 利益相关者、目标、取舍和适用场景 | 把“希望低延迟”写成已经低延迟 |
| 客观具象的条件 | 此时此地有什么可观察的事实？ | 观察者、对象/实例身份、值、时间、单位、来源与不确定性 | 把“已下载”推成“已加载”；把配置写成观测 |
| 主观具象的可选策略 | 在这些条件下可以怎样做？ | 具体动作、参数、替代方案、适用前提、资源代价和退路 | 把被选中的策略说成唯一物理必然 |
| 客观抽象的可选验证指标 | 用何种可复核规则评价观察？ | 操作化定义、单位、分母、窗口、采样范围、未知规则与阈值来源 | 把一个分数当全部目标；无数据填零；以平均数遮盖尾部 |

“客观抽象”指**指标计算定义对同一证据可复核**，不意味着选择该指标、阈值和权重是无偏或天然正确的。指标是否相关，仍由需求与场景论证。诸如完整产物、身份匹配、鉴权、资源不重叠等约束，若已经成为当前目标的必要条件，不因“指标可选”而变成可以忽略的失败。

策略与条件之间有反馈，但不能互换：选择“单 A100 独占 GPU 租约”是策略；当前有效租约属于谁、设备实际有多少可用显存是条件。策略一旦在场景中选定，会生成本次执行的承诺与约束；换策略须重新检查条件与验证范围。

## 四个视角不是四个强制层

| 视角 | 观察对象 | 共同问题 |
| --- | --- | --- |
| 核心 core | 模块内部最小能力及不变量 | 什么输入能转换为什么输出，什么永远不能冒充成功？ |
| 交互 interaction | 模块与用户/外部模块的边界 | 谁提出意图，谁拥有状态，谁产生效果，谁确认接收？ |
| 递归 recursion | 同类契约的有限分解与组合 | 子事件怎样继承身份、预算、取消与证据责任，怎样重新汇总？ |
| 表达 expression | 同一事实在 API、面板、日志、文档中的投射 | 不同表达保留了哪些语义，丢失了哪些细节，是否会改变决策？ |

每个模块对每个视角都写四类知识，形成 4×4 矩阵。文档便于人读，JSON 便于检查结构与定位来源；JSON 没有执行解释器，不会自动改变运行程序。

## 可组合契约的设计格式

一个通用模块概念上接受 `intent + observations + selected_policy + budget + identity`，返回 `decision + effects + receipts + unresolved`。这是一份待逐步落地的通用接口设计；当前 Python 代码保留其专用类和 RPC 协议。

1. 意图不是效果：命令接收、任务派发、GPU 应用配置、产物提交分别有回执。
2. 观察带实例和时效：旧实例的 ready 不能推进新实例；进程存活不是 CUDA 前进。
3. 子模块可以再分解，但父所有者只能分配自己拥有的预算。子预算总额和同一物理资源必须联合检查，不能在两个名字下重复计算容量。
4. 子任务成功不自动代表父目标成功。父模块还要检查所有必要结果、汇合条件、取消/失败传播和清理证据；可选子任务失败是否可降级由显式策略决定。
5. 表达函数允许摘要和省略，但不得将 unknown→false/0、requested→effective、accepted→completed。不同界面的等效性是**对具体判断保持语义**，不是字符串相同。

## 状态谓词保持独立

```text
can_start(e,t) = 本次事件身份有效，当前尝试尚未开始且未终结
                 AND 必要前置事实有效
                 AND 当前策略允许
                 AND 可以原子取得所需预算
ready(m,t)     = 本实例此刻可以提供约定能力
completed(e)   = 本次事件有可追踪终态与约定结果证据
cleanup(e)     = 本事件所拥有的资源已按契约归还并确认
released(vm)   = 平台确认实例不再分配
```

上式是设计谓词，不能当成现有代码里的一个万能布尔字段。`completed` 如需区分成功/失败/取消，要保留终态类别；父目标是否满足另行判断。长驻服务可以 ready 而没有退出，失败事件可以已终结但清理未知。

重试需要显式的新尝试身份和接纳决定，不能把已终结尝试重新判成可开始。依赖判断使用实际需要的结果或能力；前置事件已终结，不能代替前置结果成功且仍然有效。

## 从观察到改进

先记录条件，再选择策略，执行后以约定指标评价，随后决定继续、调整、降级、取消或停止。反馈必须关联同一个目标和实例；不能因一次失败无限递归重试，也不能为追求指标把原目标偷偷换掉。未测量项、偏差和反例留在 `gaps`，不以补齐文档字段宣称证明完成。

四模块的机器入口见 [knowledge/index.json](../knowledge/index.json)。结构校验仅检查存在性、引用和身份；主观目标是否恰当、策略是否最优、指标是否完整仍需人和真实实验判断。
