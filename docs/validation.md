# 验证与证据边界

## 当前知识的证据层

| 层 | 本仓库实际能检查什么 | 不能自动推出 |
| --- | --- | --- |
| 结构 | 四模块/四视角/四类齐全，指标字段、引用、身份有效 | 目标适当、策略最优、指标完备 |
| 源码身份 | manifest SHA 与现有文件一致 | 源码正确、历史日志真实 |
| CPU 回归 | 在合成或本地进程条件下检查接纳、幂等、取消、预算、清理等 | CUDA、画质、任意平台兼容 |
| 有限模型穷举 | 在声明的离散起点、固定时长、资源与依赖空间内枚举可行调度和反例 | 实际云端耗时、连续或一般调度问题的最优解 |
| 设备微基准 | 特定设备、形状、软件与测量方法下的运算或传输样本 | 整个模型的 FLOPs/HBM 工作量、端到端效率、未来负载的物理上限 |
| Notebook 构建 | 自包含代码可组装、Python AST 有效、启动配置被嵌入 | 当前 Colab 可分配 GPU、依赖永远不漂移 |
| 真实 GPU 服务实验 | 指定版本、配置、输入、设备上的实际观察；历史与新增运行分别标识 | 全称正确性、通用模型兼容、数学最优 |

最终 06:03 一键启动、06:05 API 与已选公网先交付、模型下载期排队，指定取消一条，保留任务自动生成；06:20:29 完成进程清理，06:22 平台会话列表无活动会话。A100 原生 BF16 + 官方 FP32 例外；一次 Turbo 后的普通任务确认 `none` 生效。没有可比较的同输入 A/B 性能实验。

早期可选 torchao 版本阻断 PEFT 的问题修复后，最终新实例通过自动依赖早检；原 PyTorch 栈保持。未知提交含任务 ID 时按原 ID 对账；短暂 503 没有变成重复生成。原始完整记录见[固定提交的真实验收报告](https://github.com/zjj1280637679-ship-it/simple-llm-api-web/blob/3a693f121d265849783eb1588dbcae380dd5ce2c/docs/reviews/2026-11-15-bf16-browser.md)。

公开仓库只保存选定的脱敏事实、任务和媒体身份、源文件哈希。未发布原始 runtime 数据库、私有连接、签名下载链接、整份运行日志或本机路径。摘要是项目记录，不是第三方签名证明；源文件指纹和事实真实性分别评估。

## v0.1.0 建仓验证

v0.1.0 的迁移没有启动 GPU。该版本受管运行时代码与历史来源做 LF 归一后的身份核对；构建器和测试调整仓库路径，runtime README 改为仓库内入口。另补齐两项旧测试私有调用夹具的请求/实例身份，并断言绑定关系；修复一项测试的同步点，等待实际等待阶段日志写入后才检查日志，避免把开始观察误当作副作用已完成。该次迁移没有改变运行时代码。已验收原始 notebook 的 SHA 保留在 import-provenance，v0.1.0 仓库 notebook 只因 README 文档嵌入而有独立 SHA；不得将两者说成逐字节相同。后续研究代码与笔记本变更另记身份和验证范围，不继承逐字节不变的声明。

运行：

```bash
python -m pip install -r requirements-test.txt
python -m pytest
python tools/check_knowledge.py
python tools/check_publication.py
python tools/build_notebook.py --check-only --preload-acceleration lightx2v-ref2va-4step
```

v0.1.0 的本地完整 Python 回归 **644 通过、8 跳过**；8 项均为 Windows 账号缺少符号链接权限，Linux CI 可在权限允许时执行。控制台实际 JavaScript 的 Node 回归 **2 通过**。该版本结果与测试范围保存在 [v0.1.0 固定版本记录](https://github.com/zjj1280637679-ship-it/model-service-workbench/blob/v0.1.0/evidence/repository-validation.json)；CI 独立执行同一类检查。GPU 依赖不安装到 CPU 测试环境，跳过项必须在报告中明确列出，不计入通过。

`tools/check_publication.py` 只覆盖它声明的发布检查模式，不是对所有可能敏感信息的完备检测。发布前仍应审查新增文件来源与实际 diff。

## 2026-11-15 架构研究

本轮研究与上述历史基线分开记账。入口为 [实验方法](research/experimental-method.md)、[协议](../research/protocol.json)、[物理下界与经验参照](research/physical-and-empirical-bounds.md)和[研究结果](research/2026-11-15-results.md)。实际运行数字、源码身份、接纳与生成记录、清理及平台释放证据以结果文档及其引用为准，不从计划字段推断完成。

有限模型由 [check_bound_cases.py](../research/check_bound_cases.py)穷举；它使用声明的模型 tick，不是设备测得的秒。设备标定与真实服务事件分别采集。服务事件分析采用同一模型实例内的顺序和单调时间；阶段区间是主机与租约包围范围，不能直接解释成纯 CUDA 内核繁忙时间。预算采样与阶段声明占用也分别报告，不把采样最大值当作完整峰值。

分析器的自动检查项不是协议 H1—H8 的同义替换：公网先上线和模型加载期接纳要有相应客户端/服务端证据；实际精度及配置要有执行回执；完整下载要核对媒体与字节身份；平台释放要有本轮独立观察。每项假设按证据标为观察范围内支持、反驳、未充分检验或未执行，不能用“所有已运行检查通过”补齐未执行的实验。

新增研究的 CPU 回归、实际云端运行和文档/分析器事后修订要分别列明。修复分析器不能改写原始运行事件，新增断言也不能声称在早先已冻结的协议中预先定义。每次生成使用新内容，有限不同内容样本不用于证明加速倍数或稳定的尾部延迟。

0.2.0 本地完整 Python 回归为 **781 通过、8 跳过、1 条既有弃用警告**；跳过仍是 Windows 符号链接权限限制，控制台 JavaScript **2 通过**，单单元 notebook 的 AST 构建检查通过。真实研究另有 2 生成成功、1 排队取消、13 项轨迹检查通过及最终平台释放，详情见结果页。[本地验证记录](../evidence/repository-validation.json)不将 Linux CI 的未来结果预填为成功；CI 在当前提交独立运行全部 CPU 测试并重放公开研究事件。

## 更新身份记录

完成源码和知识文档改动后执行 `python tools/freeze_sources.py`，再执行知识、发布和对应回归检查。冻结工具只重算明确范围内的文件身份，不重写历史验收、不声称测试通过，也不更新记录者的观测时间。`evidence/source-manifest.json` 不包含自身或易变运行结果，避免递归自哈希。

当模型、依赖、调度、宿主、API 语义或内容条件改变，先说明变更影响的命题，再选择需要重新执行的实验。没有真实测量时保留 unknown；理论下界、CPU 模型和真实耗时的单位及覆盖范围不一致时，不进行直接比较。
